# AI 슬롭 체크리스트

red-team-reader가 모든 원고에 적용하는 검사 기준. 작가도 제출 전 셀프 체크한다.
**하드 기준** 위반 1건 = 즉시 반려. **소프트 기준**은 누적 평가 (3건 이상 위반 시 반려).

## 하드 기준 (하나라도 위반하면 반려)

| # | 항목 | 검사 방법 |
|---|---|---|
| H1 | 출처 없는 통계·수치·연구 인용 | 수치 주장마다 자료카드 대조 |
| H2 | 지어낸 사례·인용·인물 | 구체적 사례가 자료카드 또는 저자 실경험 표시 없이 등장 |
| H3 | 내용 없는 챕터: 챕터를 한 문장으로 요약했을 때 "X는 중요하다, 잘 해야 한다" 수준 | 챕터 요약 작성해보기 |
| H4 | 같은 내용의 반복으로 분량 부풀리기 (같은 주장이 표현만 바꿔 3회 이상) | 단락별 핵심 주장 목록화 |
| H5 | 실용서/AI활용법: 따라 할 수 없는 절차 (입력·결과·실패 시 대처 누락) | 절차를 실제로 시뮬레이션 |
| H6 | 결론 없는 양시론으로 끝나는 절 ("결국 균형이 중요하다", "상황에 따라 다르다"가 결론) | 각 절의 마지막 단락 검사 |

## 소프트 기준 (3건 이상 누적 시 반려)

| # | 항목 |
|---|---|
| S1 | 일반론 도입: "현대 사회에서", "4차 산업혁명 시대", "~의 중요성이 날로 커지고" 류로 시작하는 챕터/절 |
| S2 | 빈 강조 표현: "매우 중요합니다", "꼭 기억하세요", "놀랍게도" — 내용 없이 톤만 올리는 문장 |
| S3 | 모든 절이 동일 패턴 (소제목→개념 정의→불릿 3개→요약)으로 기계적 반복 |
| S4 | 두 단락 연속 구체물(숫자·고유명사·실제 상황) 0개 |
| S5 | 헤징 남발: "~수 있습니다", "~일지도 모릅니다", "일반적으로", "어느 정도" — 한 절에 5회 이상 |
| S6 | 무의미한 균형 잡기: 모든 주장 뒤에 반사적으로 "하지만 단점도 있습니다" 부착 |
| S7 | 목록병: 서술로 풀어야 할 내용까지 전부 불릿으로 처리. 챕터의 불릿 비중 30% 초과 |
| S8 | 어미 단조: 의도 없는 "~다." 단순 반복, 또는 "~죠/~요" 남용으로 인한 인포머셜 톤 |
| S9 | 챕터 말미의 형식적 요약("이번 장에서는 ~을 알아보았습니다")이 새 정보·재구성 없이 목차 재낭독 |
| S10 | 비유 인플레이션: 설명을 돕지 않는 장식성 비유 ("프롬프트는 마치 요리 레시피와 같습니다") |

## 검사 보고 형식

```
## 슬롭 검사 결과
- 하드: H1 통과 / H2 통과 / H3 위반(근거: "..." 인용 + 위치) / ...
- 소프트: 위반 N건 (목록)
- 판정: 통과 | 반려
```
