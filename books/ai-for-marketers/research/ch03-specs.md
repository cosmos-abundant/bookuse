## 카드 01: 공식 프롬프트 가이드들은 일관된 출력을 위해 동일한 구성요소를 권한다 — 역할·명시적 지시·출력 형식·예시·맥락

- **주장:** 주요 모델 제공사의 공식 프롬프트 가이드는 "일관되게 원하는 출력을 얻기 위한 입력 구조화"라는 같은 목표 아래 거의 같은 구성요소를 권한다: ① 역할/페르소나 부여, ② 명확하고 구체적인 지시(애매한 추론에 맡기지 말 것), ③ 원하는 출력 형식·제약의 명시, ④ 예시(few-shot/multishot), ⑤ 맥락·동기 제공. Anthropic은 프롬프트 엔지니어링을 "원하는 출력을 일관되게 얻기 위해 모델 입력을 구조화하는 일(structuring your inputs to a model to consistently get the outputs you want)"로 정의하며, 지시·정보 순서·요청 형식까지 포함한다고 본다.
- **출처:**
  - Anthropic, "Prompting best practices", Claude API Docs(공식). https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices — 직접 열람 완료. 명시 항목: "Be clear and direct", "Use examples effectively(few-shot/multishot, 3–5개 권장, `<example>` 태그로 구조화)", "Structure prompts with XML tags(`<instructions>`,`<context>`,`<input>`)", "Give Claude a role(시스템 프롬프트의 한 문장 역할 부여)", "Control the format of responses(원하는 것을 하라/하지 말라보다 할 것을 지시)".
  - OpenAI, "Prompt engineering" / GPT-4.1·GPT-5 prompting guide(공식). https://developers.openai.com/api/docs/guides/prompt-engineering , https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide — 명시 구조: Role and Objective / Instructions / Reasoning Steps / Output Format / Examples. "출력 형식을 명확히 지정하라(특히 출력을 다른 처리에 넘길 때)", "one-shot/few-shot 예시 포함이 가장 중요한 모범사례".
- **출처 등급:** 1차(양사 공식 문서). Anthropic 페이지는 직접 열람, OpenAI 페이지는 검색 요약+공식 URL 확인(403 아님, 단 본문 전체 직접 열람은 미완 — 집필 전 재확인 권장).
- **확인일:** 2026-06-13
- **휘발성:** [휘발성] — 가이드 문구·권장 항목은 모델 세대마다 갱신됨(예: 신모델일수록 "과한 강조 표현을 빼라"는 역방향 조언 등장). **단, "역할·지시·형식·예시·맥락"이라는 5대 구성요소 골격 자체는 세대를 넘어 안정적이다.** 본문은 이 골격을 인용하고, 모델별 세부 팁은 인용하지 말 것.
- **반대 근거:** ① 신형 모델 가이드는 "모델이 암묵적 맥락을 더 잘 이해하므로 과거만큼 장황한 프롬프트가 필요 없다"고도 말한다(OpenAI GPT-5 가이드: implicit context를 더 잘 처리). 즉 "명세가 길수록 좋다"는 단정은 틀림 — 명세의 가치는 길이가 아니라 **재현성(매번 같은 입력→비슷한 출력)**에 있다는 수위로 쓸 것. ② Anthropic 문서도 신모델에서 "CRITICAL: You MUST…" 같은 강한 표현이 오히려 과잉 반응(overtrigger)을 일으킨다고 경고 → "명세 = 강한 명령어 욱여넣기"가 아님. ③ 프롬프트 구성요소의 효과는 과업·모델별로 다르며, 가이드 권고 상당수는 통제 실험이 아니라 제공사의 경험적 권고임(아래 카드 04가 통제 실험 근거).
- **인용 방식 제안:** 직접 인용 가능(Anthropic 정의 1문장) + 5대 구성요소는 배경 지식으로. 본서의 "명세 4요소(입력 형식 고정 + 출력 형식 고정 + 판단 기준 명문화 + 예외 처리)"는 이 공식 골격의 **실무용 재구성**으로 제시할 것("이 책의 발명"으로 쓰지 말 것 — ch01 카드 07·10의 동일 주의).
- **메모:** 브리프 2항(잘 쓴 프롬프트 vs 재사용 명세) 핵심 근거. 공식 가이드들이 "한 번 잘 쓰기"가 아니라 "구조화해서 **일관되게** 얻기"를 목표로 명시한다는 점이 "명세=자산" 논지를 직접 받친다. Anthropic의 "golden rule"(맥락 없는 동료에게 보여줘서 헷갈리면 모델도 헷갈린다)은 비개발자 독자에게 잘 통하는 직접 인용 후보.

## 카드 02: 같은 입력에도 LLM 출력은 흔들린다 — temperature(샘플링 무작위성)가 1차 원인

- **주장:** LLM은 다음 토큰을 확률분포에서 '샘플링'하므로, temperature 등 샘플링 설정이 0보다 크면 같은 입력에도 매번 다른 출력이 나온다. temperature를 낮출수록(특히 0/greedy) 가장 확률 높은 토큰만 고르게 되어 출력 변동이 줄지만, **변동이 0이 되지는 않는다**(→ 카드 03). 공급사 기본값은 보통 0이 아니므로, 일반 사용자가 챗봇에서 같은 질문을 두 번 해 다른 답을 받는 것은 정상 동작이다.
- **출처:** OpenAI API 문서(temperature/seed 설명) 및 Anthropic 공식 가이드(샘플링 기반 출력 정의). 보조 설명: Unstract, "Why is deterministic output from LLMs nearly impossible?" https://unstract.com/blog/understanding-why-deterministic-output-from-llms-is-nearly-impossible/
- **출처 등급:** 1차(공급사 API 문서가 temperature/seed의 동작을 명시) + 3차 해설(개념 설명 보조). 본문에서 수치 주장은 하지 않고 메커니즘만 서술하므로 등급 충분.
- **확인일:** 2026-06-13
- **휘발성:** [휘발성] — 기본 temperature 값·seed 지원 여부는 공급사·모델별로 다르고 바뀜. "기본값이 0이 아니다"는 일반 서술로 쓰고 특정 숫자 단정 금지.
- **반대 근거:** "temperature=0으로 두면 결정적이 된다"는 흔한 믿음은 부분적으로만 맞다 → 카드 03이 이 반대 근거의 본체. 본문에서 "temperature를 0으로 하면 같은 답이 나온다"고 단정하지 말 것.
- **인용 방식 제안:** 배경 지식으로(메커니즘 설명). 일반 독자용으로 "AI는 매번 주사위를 다시 굴린다, 다만 굴림의 무작위성을 줄일 수는 있다" 수준의 비유 권장.
- **메모:** 브리프 3항("출력 변동성은 버그가 아니라 전제") 핵심. **김지유가 같은 보고서 코멘트를 두 번 시켜 다른 결과를 받은 장면의 1차적 설명이 바로 이 카드다.** 단 "그러니 챗봇 사용자는 temperature를 0으로 맞추면 된다"는 처방으로 빠지지 말 것 — 대부분의 마케터는 일반 챗 UI를 쓰며 거기엔 temperature 노출이 없다. 그래서 해법이 "설정 조정"이 아니라 "명세로 변동 범위를 가두기"가 된다(챕터 논지와 연결).

## 카드 03: [핵심 반대 근거] temperature=0(greedy)이어도 출력은 완전히 결정적이지 않다 — 원인은 인프라(배치·부동소수점·하드웨어)

- **주장:** temperature를 0으로 두어 항상 최고확률 토큰을 고르는 greedy decoding을 써도, 상용 LLM 추론은 실행마다 출력이 달라질 수 있다. 이는 모델의 의도된 무작위성이 아니라 인프라 차원의 수치 비결정성 때문이다. Thinking Machines Lab(2025.9, Horace He 외)은 흔한 설명("동시성+부동소수점 비결합성")만으로는 부족하며, 핵심 원인은 **배치 불변성(batch invariance)의 결여** — 같은 요청이라도 서버가 함께 묶어 처리하는 다른 요청의 양(배치 크기)에 따라 연산 결과가 미세하게 달라져 토큰이 갈린다고 본다. 이들은 커널을 배치 불변으로 만들면 Qwen3-8B에서 1,000회 실행이 비트 단위로 동일한 출력을 내도록 만들 수 있음을 보였다(즉 비결정성은 원리적 한계가 아니라 공학적으로 제거 가능하지만, 표준 상용 엔드포인트는 그렇게 운영되지 않는다).
- **출처:**
  - (1차) Thinking Machines Lab, "Defeating Nondeterminism in LLM Inference", 2025-09(저자 Horace He 외). https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/ — **원문 403, 직접 열람 실패.** 내용은 Simon Willison 정리(https://simonwillison.net/2025/Sep/11/defeating-nondeterminism/)와 NextBigFuture·Medium 복수 2차로 교차 확인.
  - (1차 학술) "Non-Determinism of 'Deterministic' LLM Settings", arXiv:2408.04667 — greedy 설정에서도 반복 실행 간 정확도가 최대 ~15%p 변동, 최선·최악 성능 격차 최대 ~70%p; 어떤 LLM도 반복 시 동일 출력 문자열은커녕 일관된 정확도조차 보장 못 함. (arXiv 403 — 검색 요약 교차 확인, 집필 전 PDF 재확인 필요)
  - (1차 학술) "Understanding and Mitigating Numerical Sources of Nondeterminism in LLM Inference", arXiv:2506.09501 — 부동소수점 정밀도가 핵심 변수: FP32는 거의 완전 재현, BF16는 불안정(추론모델에서 AIME'24 정확도 표준편차 최대 ~9%); 배치 비불변성으로 greedy·temp0에서도 토큰 갈림. (arXiv 403 — 검색 요약 교차 확인)
- **출처 등급:** 1차(연구 블로그+arXiv 논문 2편). 단 3건 모두 원문 직접 열람 실패(403) → 복수 2차 교차로 수치 확인. **본문에서 수치(15%, 9%, 1,000회 등)를 인용하려면 집필 전 원문 재확인 필수.**
- **확인일:** 2026-06-13
- **휘발성:** [휘발성] — 추론 인프라는 빠르게 바뀜(예: SGLang 등이 배치 불변 커널을 채택해 결정적 추론을 제공하기 시작). "현재 상용 엔드포인트는 보통 비결정적이다"는 2026년 현재 서술로 쓰고, 시점을 박을 것.
- **반대 근거:** 이 카드 자체가 카드 02("temp 낮추면 잡힌다")에 대한 반대 근거다. **양방향 균형:** 비결정성은 (a) 원리적 불가피가 아니라 공학적으로 제거 가능하지만(Thinking Machines), (b) 표준 상용 환경에서는 사용자가 끌 수 없는 현실이며, (c) 동시에 OpenAI조차 API가 temperature·seed와 무관하게 "대체로 결정적(mostly deterministic)"일 뿐이라고 명시한다. 따라서 본문은 "AI는 영원히 흔들린다"(과장)도 "temp 0이면 같은 답"(틀림)도 아닌, **"일반 사용자가 쓰는 환경에서는 같은 입력에도 출력이 미세하게~상당히 달라질 수 있고, 이를 사용자가 끄기는 어렵다"**는 정확한 수위로 써야 한다.
- **인용 방식 제안:** 배경 지식으로(메커니즘) + 필요 시 한 줄 직접 인용(Thinking Machines 제목/요지). 수치는 재확인 후에만.
- **메모:** **브리프 3항의 이론적 척추.** 비개발자 마케터에게 배치 불변성·부동소수점을 길게 설명하지 말 것 — "서버가 내 요청을 다른 사람 요청과 같이 묶어 계산하는데, 그 묶음이 매번 달라서 결과가 미세하게 흔들린다"는 한 문장 비유면 충분. 핵심 메시지: **흔들림은 당신 탓도, 프롬프트만 고치면 사라질 문제도 아니다 → 그래서 "흔들려도 쓸 수 있는 범위로 가두는" 명세가 필요하고(이 장), 마지막 흔들림은 사람이 검수한다(4장 복선).**

## 카드 04: 출력 형식을 스키마로 강제하면 형식 일관성이 극적으로 오른다 — Structured Outputs 100% vs 프롬프트만 40% 미만

- **주장:** 출력 형식을 자연어로 부탁하는 것과, 스키마로 강제하는 것은 일관성에서 큰 차이를 낸다. OpenAI는 2024년 9월 Structured Outputs(개발자가 제공한 JSON 스키마에 출력이 정확히 일치하도록 보장하는 기능)를 발표하며, 복잡한 JSON 스키마 준수 평가에서 Structured Outputs를 적용한 gpt-4o-2024-08-06은 100%를 기록한 반면, 기능 없이 프롬프트만으로는(gpt-4-0613 기준) 40% 미만이었다고 보고했다. 다만 'JSON 모드'는 유효한 JSON을 유도할 뿐 특정 스키마 준수를 보장하지는 않으며, 스키마 강제는 별도 기능이다. few-shot 예시 제공 역시 출력 형식 일관성을 높이는 일반적 기법이다.
- **출처:**

### B. 실측 절차 (재현 가능하도록 고정)

1. **명세 1개를 고정한다.** 김지유 보고서 코멘트 명세(카드 01·04 기준 = 역할 + 입력 형식 + 출력 형식 + 판단 기준 + 예외 처리 5요소를 갖춘 완성형)를 1개 작성. 이 명세 전문을 본문에도 그대로 수록(ai-howto 스타일가이드: 프롬프트 전문 수록 의무).
2. **동일 명세 + 동일 입력 데이터를 세 모델에 각각 넣는다.** 같은 텍스트를 복붙(모델별로 프롬프트를 바꾸지 말 것 — "명세가 탄탄하면 도구가 달라도 쓸 만하다"가 입증 목표이므로 변수는 모델 하나여야 함).
3. **변동성 측정: 같은 모델에 같은 명세를 2~3회 반복 입력**한다(새 대화로). 회차별 출력을 모두 보존.
4. **각 출력에 캡션을 단다:** 모델명·버전(UI 표시 그대로), 실측 날짜·시각, 회차. 예: "Claude Opus 4.8 — 2026-06-?? 1회차".
5. **요약 수록 시 '요약임'을 명시**한다(브리프 지시). 전문 수록이 원칙, 길면 요약 표시.
6. **차이 평가는 우열이 아니라 '명세 충족 여부'로** 한다: (a) 출력 형식을 명세대로 지켰는가, (b) 판단 기준을 적용했는가, (c) 예외 처리를 했는가, (d) 같은 모델 회차 간 변동 폭은 "쓸 수 있는 범위" 안인가. → 이 평가표가 "변동성은 전제, 명세로 범위를 가둔다"의 실증.

### C. 실측 결과가 본문에 미치는 영향 (사전 합의)

- 세 모델 모두 명세를 대체로 충족하면 → 챕터 핵심 주장("명세가 탄탄하면 도구가 달라도 쓸 만하다") 성립. 그대로 진행.
- **만약 한 모델이 명세를 크게 벗어나거나, 같은 모델 회차 간 변동이 "쓸 수 없는 범위"로 크면** → 챕터 4항의 결론을 "도구 무관"에서 "도구별로 명세 준수도가 다르니 자기 도구로 1회 검증하라"로 수정해야 함. (= 챕터 방향 변경 트리거. 실측 후 발행인 판단 필요.)
