# ch05 보강 자료카드 (ch05-build) — 집필용 "절차 원리" 부족분

- 조사일: 2026-06-13 (researcher)
- 목적: ch05-spike.md(카드 1~15 + V-1 발행인 실측)로 경로는 이미 확정됨. 이 파일은 **집필에 필요한 "어떻게 연결하나"의 절차 원리만** 보강한다. 중복 조사 금지 원칙에 따라, 스파이크가 이미 다룬 내용(HMAC 인증 자체, 노코드 도구 기성 커넥터 부재, 아임리포트·메타 Make·구글 부가기능의 *존재 사실*, 시트 허브 논거, 가격)은 다시 만들지 않았다. 여기서는 그 위에 "설치·발급·연결의 단계 원리"를 얹는다.
- 조사 제약 고지(스파이크와 동일 양상): 공식·1차 페이지 다수가 자동화 접근 차단(HTTP 403)이었다 — guide.bati.ai(바티 가이드), workspace.google.com 마켓플레이스 상세, support.google.com(구글 광고 헬프 원문), make.com 템플릿/통합 페이지, coupler.io/owox 블로그, ko.wikipedia.org(CSV) 등. 해당 항목은 검색 엔진이 추출한 공식 페이지 본문 요약 + 복수 2차/커뮤니티 교차 확인으로 메웠고, **각 카드에 "출간 전 원문 재확인" 표시**를 달았다. 절차의 정확한 클릭 위치·가격은 추측하지 않았다(미확인 목록 또는 V-1 발행인 실측 참조).

## 카드 16: 네이버 광고 API 키 3종은 "광고시스템 > 도구 > API 사용 관리"에서 서비스 신청 한 번으로 한 화면에서 발급·확인된다

- **주장:** 네이버 검색광고를 운영하는 계정으로 네이버 검색광고(광고플랫폼)에 로그인한 뒤, 상단 **도구** 메뉴의 **API 사용 관리**로 들어가 "네이버 검색광고 API 서비스 신청"을 완료하면, 같은 페이지에서 **CUSTOMER_ID(고객 ID)·액세스 라이선스·비밀키** 세 값을 한 번에 확인할 수 있다. 이 세 값을 외부 도구(부가기능·연동 서비스)의 입력칸에 그대로 붙여넣는 것이 연결의 전부다 — 서명(HMAC) 생성은 키를 받은 서비스 측이 대신 처리한다.
- **출처:** ① 네이버 검색광고 API 발급받기, 바티(Bati) 사용가이드, https://guide.bati.ai/service/api/naver_ads (원문 403 — 검색 엔진 추출 본문으로 절차 확인: "도구 메뉴 > API 사용관리 > 서비스 신청 → CUSTOMER_ID·액세스라이선스·비밀키 확인", 외부 도구에 복붙) ② "검색광고 API 라이선스 및 키값 발급 권한 관련 문의", naver/searchad-apidoc Issue #1296, https://github.com/naver/searchad-apidoc/issues/1296 (공식 저장소 — 키 발급 위치·권한 관련 1차 맥락) ③ "[네이버] 검색광고 API 서비스 개편 안내", 아이디어키, https://www.ideakey.co.kr/html/customer/notice_detail.html?no=242 (발급 절차 교차 확인) ④ 스파이크 카드 01(naver/searchad-apidoc README)이 "도구 > API 사용 관리에서 발급"을 이미 1차 확인함
- **출처 등급:** 1차(네이버 공식 저장소 — 발급 위치) + 2차(연동 서비스 공식 가이드 — 단계 흐름). 정확한 클릭 위치는 2차.
- **확인일:** 2026-06-13
- **휘발성:** [휘발성] — 광고시스템 UI 메뉴명·배치는 개편이 잦다. 본문은 "도구 메뉴 안 'API 사용 관리'에서 신청하면 세 값이 한 화면에 나온다" 수준으로 쓰고 버튼 좌표에 의존하지 말 것.
- **반대 근거:** 일부 — Issue #1296 등에서 보듯 "권한"(계정이 직접 운영자/관리 권한이어야 발급 가능) 이슈가 있을 수 있다. 대행사가 운영하는 계정이거나 권한이 낮으면 발급 메뉴가 안 보일 수 있음 → 본문 실패 케이스(권한 부족)와 연결. "누구나 무조건 보인다"로 단정 금지.
- **인용 방식 제안:** 절차 설명(브리프의 "은행 OTP 발급" 비유에 직접 대응 — 무엇을 한다=서비스 신청 / 무엇이 보인다=세 값 / 안 되면=권한 확인). 정확한 클릭 경로는 V-1/V-2 발행인 실측 표현을 따를 것.
- **메모:** **이 카드가 V-1의 "난도 하·키 복붙" 판정의 공개 근거다.** 스파이크 카드 01은 "HMAC 서명을 직접 만들어야 한다"의 근거였으나, 아임리포트 같은 부가기능 경로에서는 *독자가 만지는 건 키 3종 복붙까지*이고 서명은 서비스가 처리한다 — 이 분리를 본문에서 명확히. 독자에게 시키는 건 "발급 + 복붙"뿐, "서명"이 아니다.

## 카드 17: 아임리포트 연결의 사용자 단계는 "마켓플레이스에서 부가기능 설치 → 네이버 키 3종 입력 → 자동 갱신"의 3단계다

- **주장:** 아임리포트(I'm Report)는 구글 워크스페이스 마켓플레이스에서 설치하는 **구글 스프레드시트 부가기능**이며, 사용자 관점의 연결은 (1) 마켓플레이스에서 부가기능 설치, (2) 카드 16에서 발급한 네이버 광고 키 3종 입력, (3) 이후 매일 아침 검색광고 데이터(검색어·광고그룹·캠페인 성과)가 시트에 자동 갱신 — 의 3단계로 이뤄진다. 다운로드·로그인·복사·붙여넣기·정리의 반복 노동을 부가기능이 대신한다고 공식 설명된다.
- **출처:** ① 구글 워크스페이스 마켓플레이스 등록 페이지(한국어), "Naver Search Ads Data API Integration: I'm Report", https://workspace.google.com/marketplace/app/naver_search_ads_data_api_integration_im/158359210801?hl=ko (원문 403 — 등재 사실·기능 설명은 검색 엔진이 추출한 마켓플레이스 공식 설명문 기준: "매일 아침 자동 갱신, 검색어·광고그룹·캠페인 성과 연동, 200여 종 보고서 템플릿, 다운로드·로그인·복사·정리 단순노동 자동화") ② 스파이크 카드 06(동일 등재 페이지의 기능 설명 — 교차 일치) ③ V-1 발행인 실측(설치→키 입력→자동 갱신 흐름 및 가격을 실세계에서 확인)
- **출처 등급:** 1차(마켓플레이스 공식 등재 설명문 — 단 원문 직접 열람은 403) + V-1 실측 보강
- **확인일:** 2026-06-13
- **휘발성:** [휘발성] — 소규모 한국형 서드파티 SaaS. 가격·UI·존속 리스크가 도구 3종보다 높다(12장 도구 존속 리스크 최상위 사례). **출간 직전 라이브 페이지 재확인 필수.**
- **반대 근거:** 카드 16의 "권한·키 발급은 독자 몫"이 그대로 적용 — 부가기능이 서명은 대신해도 *네이버 키 발급 자체*는 독자가 광고시스템에서 직접 해야 한다(아임리포트가 네이버 계정을 대리 로그인하지 않음). 즉 "설치만 하면 끝"이 아니라 "키 발급(카드 16)이 선행"임을 정직하게.
- **인용 방식 제안:** 직접 인용(도구명·3단계 흐름·"매일 아침 자동 갱신"). 가격은 본문에 V-1 실측치(월 9,900원·14일 무료)를 쓰되 "2026년 6월 기준 + [확인필요: 출간 직전 재확인]"을 반드시.
- **메모:** 절차의 핵심 메시지 = "독자가 만지는 단계는 단 2개(설치 클릭, 키 3종 붙여넣기)이고 나머지(서명·요청·갱신)는 서비스가 한다." 이게 V-1의 "VLOOKUP 수준" 판정을 본문에서 살리는 프레임. 가격·무료 한도·설치 수·갱신 안정성의 *수치*는 추측 금지 → V-1 실측 표현만 사용.

## 카드 18: 메타 광고를 노코드로 시트에 넣는 표준 패턴은 "공식 템플릿 불러오기 → 페이스북 계정 로그인(권한 부여) → 갱신 주기 설정"이다 (API 키 발급 없음)

- **주장:** 메타(페이스북) 광고 데이터를 코드 없이 구글 시트에 적재하는 2026년 6월 표준 경로는, Make의 **Facebook Insights 공식 템플릿을 불러와**(Templates에서 검색 → "Create new scenario from template") 시나리오를 만들고, **자기 페이스북/메타 계정으로 로그인해 권한을 부여(OAuth)** 한 뒤, 실행 주기(예: 매일/요일별/N분 간격)를 고르는 방식이다. 네이버와 결정적으로 다른 점: **키를 발급해 복붙하지 않고, 계정 로그인 한 번으로 인증이 끝난다**(서명·키 발급 단계 자체가 없다). 동일 패턴을 Coupler.io·OWOX 등 구글 시트 부가기능형 커넥터도 제공하며, 모두 OAuth(계정 로그인) 인증 + 예약 자동 갱신을 쓴다.
- **출처:** ① 공식 템플릿 "Sync Facebook Ad Insights to Google Sheets & Slack", Make, https://www.make.com/en/templates/11720-... (원문 403 — 단계는 검색 추출 본문: 템플릿 검색 → "Create new scenario from template" → Run scenario 주기 선택) ② Facebook Insights × Google Sheets 통합 페이지, Make, https://www.make.com/en/integrations/facebook-insights/google-sheets (403 — 통합 존재 확인) ③ "How to Connect Facebook Ads to Google Sheets Without Coding", Coupler.io Blog, https://blog.coupler.io/facebook-ads-to-google-sheets/ (403 — 검색 추출: OAuth 계정 로그인, 15분~월간 예약 갱신) ④ "Free Facebook Ads to Google Sheets Connector", OWOX, https://www.owox.com/blog/articles/free-facebook-ads-connector-to-google-sheets (403 — 검색 추출: OAuth 인증, Report Trigger로 일/주/월/커스텀 예약) ⑤ 스파이크 카드 07(Make Facebook Insights 앱·공식 보고서 템플릿 존재 — 교차 일치)
- **출처 등급:** 1차(Make 공식 템플릿·통합의 존재) + 2차(커넥터 업체 가이드 — 단계 흐름·OAuth 패턴). 원문 직접 열람은 대부분 403.
- **확인일:** 2026-06-13
- **휘발성:** [휘발성] — 메타 마케팅 API는 버전 폐기 주기가 빠르다(연 2~3회). 템플릿 번호·모듈 필드·권한 요구가 바뀔 수 있음. **출간 전 원문 재확인.**
- **반대 근거:** 있음(스파이크 카드 07의 반대 근거 유지) — 실제 마찰은 "서명"이 아니라 **메타 비즈니스 계정의 권한 부여**다. 검색 결과에서도 "비즈니스 설정 > 사용자 > 사람에서 해당 이메일을 최소 'Employee' 권한으로 추가하고 광고 계정 권한을 부여"하는 사전 작업이 필요함이 반복 확인됨. 즉 "클릭 몇 번이면 끝"이 아니라 "키 발급 벽은 없으나 계정 권한 설정이 있을 수 있다" 수위로 쓸 것. (V-4 발행인 실측이 이 마찰의 실제 강도를 확정)

- **메모:** 본문 채널 대비의 핵심: **네이버 = 키 3종 발급해서 복붙 / 메타·구글 = 내 계정으로 로그인(키 발급 없음).** 이 한 줄이 "네이버 키 발급이 유일한 진입 장벽"이라는 브리프 4번 논거를 떠받친다.

## 카드 19: 구글 광고 "공식" 시트 부가기능은 영어 시트·미국 한정이라 한국 독자 기본 경로가 될 수 없다 — 구글 채널도 OAuth 커넥터로 연결한다 (V-5 해소)

- **주장:** 구글 광고의 **공식** Google Sheets 부가기능은 보고서 생성·예약 새로고침(일/주/월)을 지원하지만, **"영어 버전 Google Sheets에서만, 미국에서만" 제공**된다 — 한국 계정·한국어 시트 사용자에게는 "Sorry, this app is not available for your country"가 뜨는 사례가 공식 커뮤니티에 다수 보고된다. 따라서 한국 독자의 구글 광고 → 시트 기본 경로는 공식 부가기능이 아니라, **메타와 동일한 OAuth(구글 계정 로그인) 방식의 서드파티 커넥터/노코드 도구**(Coupler.io, Dataslayer, Two Minute Reports, Make/n8n의 Google Ads 커넥터 등)다. 이들은 키 발급 없이 구글 계정 로그인으로 인증하고 예약 갱신을 제공한다.
- **출처:** ① "About the add-on for Google Sheets", Google Ads Help, https://support.google.com/google-ads/answer/9000139 (원문 403 — 검색 추출 공식 문구: 영어 Google Sheets·미국 한정 / 보고서 생성·"Schedule this report"로 일·주·월 자동 새로고침) ② "Google Ads Add-on for Google Sheets says 'Sorry, this app is not available for your country'", Google Ads 공식 커뮤니티 스레드, https://support.google.com/google-ads/thread/27580213 (지역 차단 실증) ③ "...not available in UK?", Google Workspace Admin 커뮤니티, https://support.google.com/a/thread/25644468 (영국에서도 막힘 — 미국 한정의 방증) ④ "Connect Google Ads to Google Sheets in 5 Minutes (2026)", Dataslayer, https://www.dataslayer.ai/blog/...2025 (403 — 서드파티 노코드 경로 존재) ⑤ Google Ads | Coupler.io Help Center, https://docs.coupler.io/sources/category/ppc/google-ads + Coupler 검색 추출(Google Ads는 OAuth 인증, 15분~월간 예약 갱신) ⑥ 스파이크 카드 08(언어/지역 제한 "미해소"로 남겨둔 항목 — **이 카드가 그 V-5를 해소함**)
- **출처 등급:** 1차(구글 공식 헬프 문구 — 원문 403, 검색 추출) + 1차(구글 공식 커뮤니티 차단 사례) + 2차(서드파티 커넥터 가이드)
- **확인일:** 2026-06-13
- **휘발성:** [휘발성] — 구글이 지역 제한을 풀면 공식 부가기능이 기본 경로 후보가 될 수 있다. **출간 전 재확인.** 현재(2026-06) 기준으로는 한국 기본 경로 = 서드파티 OAuth 커넥터.
- **반대 근거:** 부분적 반론 — 구글 워크스페이스 *언어/계정 지역*을 영어·미국으로 바꾸면 우회 사용했다는 커뮤니티 후기가 있으나, 이는 페르소나가 할 일이 아니고 권장 불가(언어 전체를 바꿔야 함). 따라서 본문은 "공식 부가기능은 현재 한국에서 막혀 있으니 기본 경로로 쓰지 않는다"가 정확한 수위.

## 카드 20: "값을 구분자로 나눠 표의 칸에 적재한다"는 개념은 CSV의 원리이며, 비개발자에게 안전하게 설명 가능하다 (저자 경험의 개념 핵심 뒷받침)

- **주장:** 데이터를 표(시트)에 자동으로 채울 때 도구가 내부에서 하는 일의 원리는 CSV(Comma-Separated Values)와 같다 — **하나의 구분자(쉼표·세미콜론·탭 등)로 값을 끊어, 구분자를 기준으로 각 값을 별도의 칸(열)으로, 줄바꿈을 기준으로 각 행(레코드)으로 나눠 적재**한다. 구분자는 표준이 정해져 있지 않고 "주고받는 양쪽이 약속만 지키면" 무엇이든 되며(그래서 숫자에 쉼표가 섞이면 세미콜론을 쓰기도 한다), 노코드 커넥터·부가기능은 이 "값을 끊어 칸에 넣는" 일을 사용자 대신 처리한다. **독자는 이 원리를 이해만 하면 되고, 직접 구분자를 다루거나 파싱하지 않는다.**
- **출처:** ① "CSV (파일 형식)", 위키백과, https://ko.wikipedia.org/wiki/CSV_(파일_형식) (원문 403 — 검색 추출 핵심 문장: "구분 문자(쉼표·세미콜론·탭 등 한 문자)로 필드 구별 / 필드 구분자·레코드 구분자 둘만 필수 / 표준이 없어 양쪽이 약속만 지키면 됨 / 숫자에 쉼표 포함 시 세미콜론 사용") ② "4.2 데이터 입출력 - CSV 파일 입력", 데이터사이언스스쿨, https://datascienceschool.net/01%20python/04.02... - **확인일:** 2026-06-13

- **반대 근거:** 없음(검색 불필요한 정의적 사실). 다만 **페르소나 가드레일 반대 방향의 주의**가 핵심: 저자 경험 원형은 "AI API가 구분자 형식으로 값을 뱉게 해서 적재"였는데, 이는 개발 영역이다. 본문은 *원리 설명*까지만 쓰고 *독자에게 시키지 않는다* — 노코드 도구가 이 일을 대신함을 보여주는 데까지만.
