# 챕터 브리프: ch10 (자동화가 깨지는 7가지 패턴과 응급 처치)

3부(운영편) 첫 장. 2부에서 만든 시스템이 실제로 굴러가다 깨질 때의 대응. 기획안 10장.

⚠️ **ch12 인계(경계 분담, 필수):** 모델 교체로 인한 출력 변화는 — "출력이 아예 안 나옴 = 10장 응급 처치 / 출력은 나오는데 톤·골격이 바뀜 = 12장 명세 점검(과적합 회피)". 10장은 **응급 복구**(끊긴 것 되살리기)를, 12장은 **낡음 대응**(명세 이식)을 맡는다. 이 분담을 본문에 명시.

- **독자가 얻는 것 (한 줄):** 어느 날 보고서가 안 와 있을 때, 패닉 없이 30분 안에 원인을 좁힌다.
- **이 챕터가 답하는 질문:** "자동화를 믿고 있었는데 월요일에 보고서가 비어 있다. 코드도 모르는 내가 뭘 어떻게 고치나?"
- **다뤄야 할 핵심 내용:**
  1. **도입:** 김지유가 월요일 아침 시트를 열었는데 데이터가 안 들어와 있는 장면. 패닉이 아니라 절차로.
  2. **자동화가 깨지는 7가지 패턴:** 연결(인증) 만료, 데이터 형식 변경(소스가 열 이름 바꿈), 모델 업데이트로 출력 변화(→경계: 안 나옴=10장/톤만 바뀜=12장), 한도·쿼터 초과, 권한 변경, 소스 사이트/페이지 구조 변경, 무음 실패(에러 없이 빈 결과). 각 패턴의 증상·원인·응급 처치.
  3. **진단 순서(코드 없이):** 패닉 없이 원인을 좁히는 순서 — 어디부터 보나(출력 자리→연결 상태→소스→로그). 30분 안에 원인 격리.
  4. **응급 처치 vs 근본 수리 구분:** 당장 이번 주 보고서를 살리는 임시 대처(수동 우회)와 다음을 위한 수리. (5장 플랜 B가 응급 우회로 회수)
  5. **무음 실패가 가장 위험:** 에러도 안 나고 그냥 빈 결과 — 4장 검수가 이걸 잡는 마지막 그물(검수 회수).
  6. **실행 과제:** 자기 자동화에 "안 왔을 때 30분 진단" 체크리스트 한 장 미리 만들기.
- **다루지 않는 것:** 자동화 구축(2부), 통합 설계(9장 — 느슨한 결합은 거기), 도구 낡음·교체(12장 — 경계 명시), 보안 사고(11장). 1~9장 재설명 금지.
- **자료카드:** `research/ch10-failures.md`
  - 노코드 자동화/API 연동의 흔한 실패 모드(인증 만료, 스키마 변경, rate limit, silent failure 등) 근거. 1차/공식 문서 우선.
  - "무음 실패(silent failure)"가 탐지 어렵고 위험하다는 근거.
  - 모델 deprecation/업데이트로 인한 출력 변화(ch12 카드 재활용 — 경계용).
  - 비개발자의 장애 진단(트러블슈팅 순서) 모범 근거.
  - 반대 근거: 과한 모니터링·알림의 비용(7장 알림 피로 연결).
- **예상 분량:** 10,000자 (±20%)
- **앞뒤 연결:** 2부(만든 시스템) 받음. ch04(검수=무음 실패 그물)·ch05(플랜 B=응급 우회)·ch07(알림)·ch09(느슨한 결합=장애 국소화) 회수. ch12(낡음)와 경계 분담. 3부 첫 장.
