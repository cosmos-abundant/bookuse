# 챕터 브리프: ch06 ([프로젝트 1-B] 주간 성과 보고서: 분석·초안·슬라이드 생성)

2부 둘째 장. ch05의 "통합 분류표 탭"을 입력으로 받아 보고서를 완성한다. **이 장이 "4시간→40분" 약속의 후반부(분석+PPT)를 담당** — 기획 red-team 수정 필수 2로 PPT 변환이 정식 편입된 장.

- **독자가 얻는 것 (한 줄):** 모인 데이터에서 증감 분석 코멘트 → 보고서 초안 → 발표용 슬라이드까지 자동 생성되게 한다.
- **이 챕터가 답하는 질문:** "데이터는 시트에 모였다. 그런데 증감 계산하고, 코멘트 쓰고, PPT로 옮기는 그 나머지 2시간 넘는 일은?"
- **다뤄야 할 핵심 내용:**
  1. **도입:** ch05로 데이터는 모였다. 김지유의 월요일에 남은 것 — 증감 분석(50분) + 코멘트 + PPT 정리. 이 장이 그걸 자동 생성으로 바꾸고, 남는 건 검수 40분.
  2. **3장 명세를 실제 보고서 명세로 완성:** ch03의 v1 코멘트 명세(역할+입력+출력+판단+예외)를 주간 보고서 전체 명세로 키운다. 전문 수록 + 실제 출력 + 평가(ai-howto 재현성). 전주 대비/목표 대비/이상치 탐지를 AI에 시키는 법.
  3. **수치 검증은 사람이 — 4장 적용 + 핵심 처방:** ch04의 복선("계산을 LLM 텍스트 생성에 맡기지 말고 스프레드시트/코드 인터프리터에 맡겨라" — Apple GSM-Symbolic 근거)을 여기서 회수·실행. **증감률 등 계산은 시트 수식이 하고, AI는 그 숫자를 해석·서술만.** AI에게 암산시키지 않기. 이게 "그럴듯한 오답 숫자"를 막는 6장의 핵심.
  4. **초안 → 발표 슬라이드 변환(red-team 수정 필수 2):** 텍스트 초안에서 끝나면 약속이 깨진다(페르소나 4시간엔 PPT 포함). 회사 표준 템플릿 위에 슬라이드가 채워지는 노코드 경로(2026년 6월 기준 도구·버전 — AI 슬라이드 생성 또는 문서→슬라이드 자동 변환) + 그 한계(디자인 만족도·템플릿 제약).
  5. **비포/애프터 타임라인:** "만들기"에서 "검수"로. **PPT 변환 단계를 별도 행으로 명시**(자동화 전/후). "4시간→40분"의 측정 범위가 PPT까지 포함임을 못박음. ⚠️ "4시간→40분" 수치 자체는 과업 D(베타 리더 실측) 미완 — 단정 말고 "목표"로, 또는 [확인필요: 과업 D 실측].
  6. **실행 과제:** 자기 통합 탭에 보고서 명세를 적용해 코멘트 초안 한 번 생성.

- **다루지 않는 것:** 데이터 취합(5장), 모니터링(7장), 콘텐츠 변환(8장). 검수 체계 전반(4장 — 적용만). 1~5장 개념 재설명 금지(회수·참조).
