# 챕터 브리프: ch09 (시스템 연결 — 세 프로젝트를 하나의 주간 루틴으로)

2부 마지막 장. ch05~08의 세 자동화(보고서·모니터링·콘텐츠)를 하나의 운영 루틴으로 통합. 기획안 9장. **분량이 짧은 통합 장(기획 8,000자).**

- **독자가 얻는 것 (한 줄):** 개별 자동화 3개를 요일별 운영 루틴 1장짜리 표로 통합한다.
- **이 챕터가 답하는 질문:** "보고서·모니터링·콘텐츠 자동화를 따로따로 만들었다. 이걸 어떻게 매주 굴러가는 하나의 시스템으로 묶나? 서로 부딪히지 않나?"
- **다뤄야 할 핵심 내용:**
  1. **도입:** 김지유가 세 자동화를 다 만든 상태. 이제 흩어진 셋을 하나의 주간 루틴으로. (ch05~08 회수 — 재설명 말고 "이미 만든 셋"으로)
  2. **요일별 운영 루틴 1장 표:** 월(보고서)·매일 아침(모니터링 브리핑)·수시(콘텐츠)를 한 표에 배치. 각 자동화가 언제 돌고 사람이 언제 검수하는지. "검수 40분"이 주간에 어떻게 분산되는지.
  3. **자동화끼리 연결할 때의 연쇄 오류와 차단법:** 하나가 깨지면 다음이 망가지는 도미노. 자동화를 느슨하게 결합(하나 실패해도 나머지 도는)하는 법. (10장 장애 대응의 예고 — 여기는 설계, 거기는 대응)
  4. **주간 점검 10분 루틴:** 매주 시스템이 제대로 돌았는지 확인하는 짧은 체크. 무엇을 보는가.
  5. **동료에게 넘겨줄 때 문서화:** 자동화를 혼자만 아는 상태로 두면 휴가도 못 간다. 인수인계 문서 최소 요소.
  6. **실행 과제:** 자기 자동화들을 요일별 표 한 장으로 그리기.
- **다루지 않는 것:** 개별 자동화 구축(5~8장 — 회수만), 장애 대응 상세(10장), 보안(11장), 도구 교체(12장). 1~8장 재설명 금지.
- **자료카드:** `research/ch09-integration.md` (가벼운 조사 — 이 장은 통합/운영 원리 중심이라 신규 사실 주장이 적다)
  - 자동화 시스템의 느슨한 결합(loose coupling)·연쇄 실패(cascading failure) 원리 근거.
  - 개인 워크플로 문서화/인수인계 모범 근거.
  - 주간 운영 점검(루틴 점검) 관련 근거.
  - 기존 카드 재활용 우선(ch05~08, ch04 검수). 신규 최소화.
  - 반대 근거: 과한 통합의 위험(한 시스템에 다 묶으면 한 번에 다 깨짐).
- **예상 분량:** 8,000자 (±20%)
- **앞뒤 연결:** ch05·06·07·08(세 자동화) 회수해 묶음. ch04(검수) 회수. 3부(10장 장애·11장 보안·12장 교체)로 넘김 — "이제 만들었으니, 굴리다 깨지고 낡는 것을 3부에서." 2부를 닫고 3부로 여는 다리 장.
- **스타일 유의:** ai-howto + practical + common + 용어집. 페르소나 가드레일: 코드 한 줄 없이. ⚠️ 무결성(ch06 H2): 가짜 출력/사례 금지, 형식 예시는 라벨. 짧은 장이니 군더더기 없이. 첫 문단 일반론 금지. 2부를 닫는 장이므로 "원리(1부)로 프로젝트(2부)를 지었다, 이제 운영(3부)"의 다리 역할.
