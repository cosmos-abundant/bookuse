# 챕터 브리프: ch03 (프롬프트가 아니라 '업무 명세'를 써라)

- **독자가 얻는 것 (한 줄):** AI에게 일을 시킬 때 매번 결과가 달라지는 문제를, 재사용 가능한 '업무 명세'로 잡는다.
- **이 챕터가 답하는 질문:** "같은 걸 시켰는데 왜 어제 결과랑 오늘 결과가 다르지? 어떻게 하면 매번 같은 품질로 나오게 하나?"
- **다뤄야 할 핵심 내용:**
  1. **회수: ch02에서 "왼쪽 위(규칙 애매)"로 떨어진 일을 오른쪽으로 옮기는 도구가 명세다.** 도입은 김지유가 같은 보고서 코멘트를 두 번 시켰는데 다른 결과가 나온 장면으로. ch02 매트릭스의 "명세부터 정비" 사분면을 여기서 실행.
  2. **잘 쓴 프롬프트 vs 재사용 가능한 명세의 차이.** 일회성 대화와 매주 돌릴 자산의 차이. 명세 = 입력 형식 고정 + 출력 형식 고정 + 판단 기준 명문화 + 예외 처리 지시. 4요소 각각 김지유 사례로.
  3. **출력 변동성은 버그가 아니라 전제다.** 같은 명세라도 출력은 흔들린다 — 이걸 0으로 만드는 게 아니라 "흔들려도 쓸 수 있는 범위"로 가두는 게 명세의 목적. (4장 검증 체계로 연결)
  4. **같은 명세를 ChatGPT·Claude·Gemini에 넣은 실제 출력 비교.** 전문 수록 + 실제 출력(요약 시 요약임을 표시) + 차이 평가. 도구별 우열이 아니라 "명세가 탄탄하면 도구가 달라도 쓸 만한 결과가 나온다"를 보이는 게 목적.
  5. **명세 작성 실전:** 빈약한 프롬프트 → 명세로 키우는 before/after 1세트(김지유 보고서 코멘트 명세).
- **다루지 않는 것:** 검증 체계 상세(4장 — 변동성 언급 시 예고만), 도구 연결·자동화 구축(5장~), 도구별 기능 소개(이 책은 도구 매뉴얼이 아니다). ch02 매트릭스 재설명 금지(참조만).
- **자료카드:** `research/ch03-specs.md`
  - ⚠️ **실측 과업(이 장의 핵심):** 같은 업무 명세 1개를 2026년 6월 시점 ChatGPT·Claude·Gemini에 실제로 넣고 출력을 수집·기록. 모델 버전·날짜 명시([휘발성]). 같은 모델에 2~3회 반복 입력해 출력 변동도 기록(변동성 주장의 근거). 에이전트가 실제 실행 불가능하면 "실행 불가 — 발행인 실측 필요"로 정직하게 분리하고, 그 경우 본문 예시는 [확인필요] 처리 대상임을 명시.
  - 프롬프트 엔지니어링 → 재사용 가능 명세/구조화 프롬프트 관련 1차 근거(프롬프트 구성요소, 출력 일관성·temperature·비결정성 관련 공식 문서·연구). 카드 09(Anthropic, ch01)와 중복 피할 것.
  - LLM 출력 비결정성의 원인(같은 입력에도 출력이 달라지는 이유)에 대한 근거 — 단정 말고 정확한 수위로.
- **예상 분량:** 11,000자 (±20%) — 출력 비교 전문 수록으로 본문이 길다.
- **앞뒤 챕터 연결:** ch02에서 받음 — "명세부터 정비" 사분면, 매트릭스. ch04로 넘김 — "명세로도 못 막는 흔들림은 사람이 마지막에 검수한다." ch06으로 넘김 — 이 명세가 실제 보고서 명세로 완성됨.
- **스타일 유의:** ai-howto(프롬프트 전문 수록 의무, 버전·시점 명시, 재현성) + practical + common + 용어집 준수. 출력 비교는 표보다 실제 블록 인용으로. 1부 원리 장이되 이 장은 실측이 들어가므로 도구 버전 명시 철저히.
