# 챕터 브리프: ch05 ([프로젝트 1-A] 주간 성과 보고서: 데이터 취합 자동화)

⚠️ **이 브리프의 1차 목적은 집필이 아니라 과업 A 스파이크다.** 스파이크 판정 전에는 ch05 집필 착수 금지 (기획안 7절).

- **독자가 얻는 것 (한 줄):** 흩어진 광고 채널(네이버·메타·구글) 데이터가 한 곳에 자동으로 모이는 통로를 만든다.
- **이 챕터가 답하는 질문:** "코드를 못 읽는 내가, 채널 3곳의 데이터를 사람 손 없이 한 시트에 모을 수 있는가?"

## 과업 A 스파이크 (자료조사 1순위)

**판정 질문:** 네이버 검색광고 API(서명 인증 방식)를 노코드 도구(Make/n8n/Zapier 등)로, VLOOKUP 수준 사용자가 따라 할 수 있게 연결할 수 있는가?

- 공식 문서·커넥터 카탈로그·커뮤니티 템플릿 기준으로 채널별 연결 경로를 조사하고 난도를 판정한다: 네이버 검색광고 / 메타 광고 / 구글 광고 각각.
- 판정 결과는 셋 중 하나: **① 순수 노코드 가능**(경로 명시) / **② 페르소나 눈높이 초과 → 플랜 B(네이버만 주 1회 수동 다운로드+업로드, 이후 자동) 채택** / **③ 양쪽 모두 불가 → 편집장 에스컬레이션**.
- 문서 조사만으로 판정이 불확실한 부분은 "실제 구축 검증 필요 항목"으로 명시해 발행인 실세계 과업으로 넘긴다 (에이전트는 광고 계정·실 구축을 못 한다 — 솔직하게 한계를 보고할 것).

## 자료카드로 만들 것

1. 채널별 API/커넥터 연결 경로와 난도 (네이버 검색광고 API 인증 방식 포함, 전부 [휘발성] 태그 + 확인일)
2. 노코드 도구 3종(Make/n8n/Zapier)의 2026년 6월 기준 가격·플랜·해당 커넥터 지원 현황 [휘발성]
3. 스프레드시트 허브 패턴의 근거 (왜 DB가 아니라 시트인가 — 비개발자 관점)
4. 네이버 광고 보고서 수동 다운로드 경로·형식 (플랜 B 설계용)

- **다루지 않는 것:** 모인 데이터의 분석·보고서 생성(6장), 모니터링(7장).
- **예상 분량 (집필 시):** 13,000자
- **앞뒤 챕터 연결:** 4장의 검증 체계를 전제로 함 / 6장에 "한 시트에 모인 데이터"를 넘긴다.
- **실행 과제 후보:** 자기 회사 광고 계정의 채널 구성 목록과 각 채널 API 접근 권한 확인.
