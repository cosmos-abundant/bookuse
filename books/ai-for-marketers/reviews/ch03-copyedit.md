# ch03 교정교열 보고서

작업일: 2026-06-13 / 대상: manuscript/ch03.md
범위: 문장 단위(맞춤법·띄어쓰기·번역투·용어 통일·표기 일관성). 구조·내용 불변.
보존: [확인필요] 3건 마커 및 발행인 실측 빈 슬롯, 명세 전문(코드 블록) 구조·의미.

## 1. 일괄 수정 요약 (유형별 건수)

| 유형 | 건수 | 내용 |
|---|---|---|
| 어법 오류 | 1 | "미리 밝혀 두면" → "미리 밝혀 두자면" (조건절 오독 유발 비문 교정, 35행) |
| 표기 통일(작은따옴표) | 1 | 본문 첫 실질 등장 "업무 명세" → "'업무 명세'" (용어집 규칙 적용, 7행) |
| 띄어쓰기 + 본문/코드 통일 | 3 | 코드 블록 "이번주"(표 헤더 2개 + 예외 처리 1) → "이번 주". 본문 37행 표기와 일치시킴(맞춤법만, 코드 구조 불변) |

전수 검사 결과 깨끗했던 항목(수정 0건):
- 번역투 금지 목록("~에 있어/함에도 불구하고/라고 할 수 있다/되어지다/가지다 남용" 등) 해당 없음
- 군더더기·AI 문체 시그니처("사실/기본적으로/다양한/여러 가지/효과적으로/라는 것이다") 해당 없음
- 되/돼, 봬/뵈, 이중 피동 빈출 오류 없음
- "들" 남용 없음(19행 "요청들", 61행 "도구들"은 복수 의미상 필요 → 보존)
- 모델명 표기(ChatGPT/Claude/Gemini) 산문부 정확
- 영문 용어(temperature/Structured Outputs/few-shot) 소문자·병기 일관
- 보고서/논문 제목 「 」, 강조(굵게)·인용(" ") 규칙 준수
- 날짜·숫자 표기 일관(만 단위 없음)

## 2. 제안 항목 (편집장 판단 필요 — 의미·문체 영향 가능, 직접 미반영)

1. **"프롬프트 엔지니어링" 영문 병기(35행).** ch03 첫 등장이나 병기 없음. 스타일가이드 예시는 "프롬프트 엔지니어링(prompt engineering)". 단 용어집은 "프롬프트" 자체에 병기 불필요로 규정. 합성어 "프롬프트 엔지니어링"을 별도로 1회 병기할지 결정 요망.

2. **35행 장문(약 9문장 1단락, 핵심 문장 100자 초과 다수).** 의미 밀도 높고 줄표·괄호로 구조화돼 있어 직접 분할 시 의미 손상 위험. 분할 여부는 편집장 판단에 위임.

3. **5행 "매주 같은 일을 매주 새로 부탁하는 수동 반복".** 한 문장 내 "매주" 2회. 강조 리듬으로 보여 보존했으나, 둘째 "매주"를 삭제("같은 일을 매주 새로 부탁")해도 의미 동일. 리듬 의도면 유지.

4. **45행 "출력 형식 고정 = 양식 박기 + 예시 한 개" 등식 표기.** 산문 내 =, + 기호 사용. "등식"이라 명시해 의도적이고 명세의 × 표기 관용과 결이 맞아 보존. 산문 가독성 차원에서 풀어쓸지 검토 가능.

## 3. 용어집 추가 항목 (9건)

핵심 개념어:
- 명세 4요소(입력/출력/판단/예외 + 머리말 역할)
- 예시 동봉(few-shot 병기 규칙)
- 비결정성(평이어 "흔들림" 우선, 학술 문맥만 "비결정성")
- 업무 명세 비고에 "본문 첫 실질 등장에 작은따옴표 적용" 보강

AI 일반:
- temperature(영문 소문자 고정)
- Structured Outputs(API 기능명 영문 고정)
- few-shot(소문자 하이픈 고정)
- 출력 변동성(= 흔들림 풀이, 평이어 우선)

ChatGPT/Claude/Gemini는 기존 용어집 도구·서비스명 표에 이미 존재 → 중복 미추가, 본문 표기 준수 확인만.
