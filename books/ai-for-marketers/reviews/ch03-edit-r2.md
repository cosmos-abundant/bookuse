## 총평 (3줄 이내)

r1의 P1 한 건과 P2 세 건, P3 두 건이 모두 지시 방향대로 해소됐다. 특히 P1(출력 형식 절의 정서적 역순)은 비개발자 방식을 "당신의 무기"로 먼저 완결한 뒤 API 강제를 "같은 방향의 외부 증거"로 강등하는 재배치가 깔끔하게 들어갔고, 결과적으로 독자가 결핍을 느끼는 구간이 사라졌다. 순서 재배치가 새로 만든 흐름 단절은 없다 — 절 봉합부(출력 형식→판단 기준, 4요소→"네 칸을 다 채워도 남는 것")가 오히려 r1보다 매끄럽다. 빈 실측 슬롯은 발행인 대기 항목이므로 결함으로 잡지 않는다.

## 잘된 점 (지키면서 고칠 것)

1. **P1 해소가 단순 순서 교체를 넘어 "무기 → 외부 증거" 위계로 재설계됐다(41~47단락).** 41단락이 "둘 다 챗 화면에서 지금 바로 할 수 있다 … 이 둘이 당신의 무기다"로 비개발자 방식을 선언하고, 42·45단락이 양식 박기·예시 동봉(few-shot)을 각각 펼친 뒤 45단락 끝에서 "비개발자의 출력 형식 고정 = 양식 박기 + 예시 한 개"라는 등식을 못 박는다. 그제야 47단락이 "방향이 맞다는 외부 증거도 있다"로 API/Structured Outputs를 꺼내고 "당신에게 없는 상위 도구가 아니다"로 닫는다. r1 지시의 핵심(수치가 상위 호환으로 먼저 등장하면 안 된다)을 정확히 충족했다. 이 위계는 보존할 것.

2. **P2-4 결론 분기 중립화가 본문 선행 서술에서 양쪽을 동등하게 받는다(63단락).** "일등 공신은 도구 선택이 아니라 명세의 품질일 가능성이 크다 … 다만 이건 주장으로 끝낼 게 아니라 당신 손으로 확인할 일이다 — 도구마다 명세를 받아 주는 정도가 다를 수도 있고, 그렇다면 그것 또한 당신이 알아야 할 정보다." 79단락 분기([확인필요] 4번)가 어느 쪽으로 확정되든(도구 무관 / 도구별 1회 검증 필수) 63단락을 거의 손대지 않고 자연 완성된다. 자료카드 C의 "어느 결과든 자연 완성" 설계 의도가 본문까지 도달했다. 보존.

## 순서 재배치가 만든 신규 문제 점검 (의뢰 ②)

- **출력 형식 절 봉합부:** 41(무기 선언) → 42(양식) → 45(예시+등식) → 47(외부 증거) → 49(판단 기준)로 이어지는 흐름에 단절 없음. 47단락이 "같은 방향의 두 손잡이일 뿐"으로 닫고 49단락 판단 기준으로 넘어가는 전환 자연스럽다.
- **4요소 → 한계 격상부:** 53(예외 처리) → 55(네 칸 채우면 한 장 문서) → 57("다만 네 칸을 다 채워도 남는 게 있다") 순서로, r1에서 출력 형식 절 안에 끼어 있던 한계 메시지가 절 끝으로 빠지면서 오히려 논리 동선이 정돈됐다. 신규 단절 없음.
- **명세 전문 캡션(104~105단락):** "이 명세는 도구·시점과 무관한 자산으로 설계했고, 도구별 동작 차이는 … 4단계로 확인한다"가 3절 검증 프로토콜과 호응. 35단락 역할 명시 → 전문 # 역할(107~110)로 이어지는 요소 개수 일관성도 봉합 후 깨끗하다.
