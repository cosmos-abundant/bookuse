# ch03 교정교열 보고 — V-2 실측 신규부

대상: `manuscript/ch03.md` 중 "명세가 탄탄하면 도구가 달라도 쓸 만하다" 절 내
V-2 실측 신규 부분만(실측 도입 문장, 출력 블록 2개, 차이 분석 단락, 명세 준수 채점표, 결론).
그 외 기존 교정 완료부는 손대지 않음. (작성: 2026-06-13)

## 1. 일괄 수정 요약 (유형별 건수)

- **모델명 표기 통일: 1건**
  - "Google Gemini 3.5 Flash" → "Gemini 3.5 Flash"
    (출력 블록 라벨·채점표 헤더·용어집과 통일. "Google" 접두 제거)
- **용어 통일(표 칸 수 표기): 2건**
  - "6칸 표" → "여섯 칸 표" (실측 도입 단락 1건, 입력 설명 단락 1건)
    본문 프로즈 다른 곳(여섯 칸짜리 표/여섯 칸 표 형식)과 일치시킴.
- 맞춤법·띄어쓰기 오류: 0건 (신규부 프로즈에서 추가 오류 없음)
- 번역투·군더더기: 0건 (common.md 금지 목록 전수 검사 — 해당 없음)
- 리듬(어미 3연속/80자 초과): 직접 수정 0건 (아래 제안 참고)

총 직접 수정 3건.

## 2. 제안 항목 (편집장/편집 판단 필요 — 의미·문체에 영향, 직접 수정 안 함)

1. **레지스터 혼용: "빡빡하게"(2회) vs "엄격히/엄수"(결론·표).**
   97행 "더 빡빡하게 지키느냐", 112행 "어느 칸을 빡빡하게 지키는지"는 구어 톤.
   결론(114행)과 채점표는 "엄격히/엄수"로 격식체. 같은 개념(규칙 준수 강도)을
   두 어휘로 부른다. 책의 전반적 구어 톤과 어울려 오류는 아니나, 일관성 차원에서
   "빡빡하게"를 "엄격히/꼼꼼히"로 맞출지 편집 판단 요청. (의미 동일하나 톤이 바뀌어
   직접 수정하지 않음.)

2. **"외부 사실" vs "외부 원인" 혼용.**
   101행·112행은 "외부 원인", 채점표(109행)·명세 전문(157행)은 "외부 사실".
   같은 규칙(판단 기준 4번)을 가리키는 두 표현. 명세 원문이 "외부 사실"이므로
   분석 단락도 "외부 사실"로 맞추는 편이 깔끔하나, "원인을 외부에서 끌어온다"는
   문맥상 "외부 원인"이 자연스러운 자리도 있어(101행) 일률 통일 시 의미 뉘앙스가
   달라질 수 있음. 편집 판단으로 남김.

3. **"세 도구"(116행) vs 실측 두 도구.**
   116행 "지금 세 도구의 이름이 다 바뀌어도"의 "세 도구"는 4단계 절차에서 독자가
   넣어 볼 ChatGPT/Claude/Gemini 셋을 가리킴(실측은 둘). 문맥상 일관되나, 바로 앞
   실측이 두 도구였음을 막 강조한 뒤라 독자 혼동 여지. 내용 영역이라 직접 수정 안 함 —
   편집장이 "세 도구"를 유지할지(절차상 셋) 결정 요청.

## 3. 용어집 추가 (`glossary.md`)

- **도구·서비스명**에 2행 추가:
  - `Gemini 3.5 Flash` (금지: Google Gemini 3.5 Flash 등. 프로즈에서도 Google 접두 미부착)
  - `ChatGPT 무료 티어` (띄어 씀. 금지: 무료티어/free tier 등)
- **숫자·단위·기타 표기**에 3항 추가:
  - 줄표 규칙에 "실측 출력 블록·채점표 셀 안 줄표도 앞뒤 한 칸" 명문화
  - **실측 캡션 형식(3장 V-2):** "[모델명 — YYYY-MM-DD 측정]" 라벨 + 출력 본문 무수정 보존 원칙
  - **표 칸 수 표기:** 본문 프로즈 "여섯 칸 표"(6칸 표 ×), 도식 안은 보존

## 4. 실측 출력 블록 무수정 확인

- `[Gemini 3.5 Flash — 2026-06-13 측정]` 블록(현 81~86행): **무수정.** 한 글자도
  건드리지 않음. "-32%", "(추정) 타깃 피로 또는 소재 노후" 등 받은 그대로 보존.
- `[ChatGPT 무료 티어 — 2026-06-13 측정]` 블록(현 88~93행): **무수정.** "-32.3%",
  "...있었을 가능성", "...재측정한다" 등 도구 출력 그대로 보존(맞춤법 교정도 미실시).
- 두 블록은 코드펜스(```) 안에 그대로 있으며, 캡션 라벨 형식만 용어집에 기록.
- [확인필요] 마커: 이 신규부 범위(실측 도입~결론) 내에는 [확인필요] 없음.
  ch03 전체의 [확인필요] 2건(21행 SGLang, 47행 OpenAI 수치)은 신규부 밖이며 그대로 유지.
