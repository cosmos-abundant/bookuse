편집장 판단으로 "개념적 핵심"만 페르소나 눈높이로 번역해 쓰고 기술 디테일은 고급 분기/후속으로 미룬다.

## 2026-06-13 — 데이터 취합 / 배치 자동화 경험 (ch05·2부 관련)

발행인 원문:
> 데이터 취합 자동화는 AI API 호출 방식으로; 세퍼레이트(구분자) 값 받아서 엑셀에 저장할 수 있었어.
> 나만의 분류표를 만드는 느낌이었어.
> 이번에는 aibench를 만들어서 API 연결하고 폴더 안의 파일에 대해서 작업이 되도록 만들었어.
> 파일명에 마커가 붙을 수도 있고, 같은 프롬프트를 모든 파일에 대해서 적용할 수도 있고 그런 자동화를 한 거지.

편집장 해석·활용 지침:
- **개념적 핵심 (페르소나 안전, 적극 활용):** "데이터 취합 = 단순 수집이 아니라 *나만의 분류표/구조를 만드는 능동적 설계*"라는 통찰. ch05의 "시트를 허브로 쓴다"의 의미를 살리는 프레이밍으로 좋다. AI에게 구분자(예: `;`) 형식으로 값을 뱉게 해 표로 적재하는 패턴도, 노코드 도구가 내부에서 하는 일을 독자가 이해하는 데 도움.
- **배치 패턴 (개념만, 페르소나 위 주의):** "폴더 안 모든 파일에 같은 프롬프트 적용 + 파일명 마커"는 강력한 자동화 원형이다. 단 직접 'aibench를 만든다'는 개발 영역 → 김지유에게 그대로 못 준다. "같은 명세를 여러 입력에 반복 적용"이라는 원리(3장 명세 + 반복)로 번역하거나, ch08(콘텐츠 다채널 변환 = 원본 1건에 여러 변환 적용)·ch09(시스템 통합)에서 개념 사례로 검토.
- **기술 방식 자체(API 키, 구분자 파싱, 자체 도구 제작):** "코드 한 줄 없이" 약속과 충돌 → 본문 기본 경로로 쓰지 말 것. 필요 시 "더 나아가고 싶은 독자를 위한" 고급 분기 박스에서 한 발만, 또는 후속/부록 후보.
