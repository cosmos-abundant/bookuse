퇴고 단계를 오케스트레이션한다. 입력: $ARGUMENTS (책 slug + 챕터). 이 스킬이 품질의 본체다 — 단계를 건너뛰지 않는다.

## 체인 (순서 고정)

### 1) 구조 편집 루프 (최대 2라운드)
- `dev-editor` 호출: 원고, 기획안, 브리프, 인접 챕터 원고 경로 명시. 지시서를 `reviews/chNN-edit-rN.md`에 저장.
- 판정이 "수정 후 재검토"면 → `writer`(수정 모드)에게 지시서 첨부해 반영시키고 → `dev-editor` 재검토. "재집필 권고"면 사용자에게 보고 후 판단 대기.
- 2라운드 후에도 P1이 남으면: 쟁점 요약해 사용자 에스컬레이션.

### 2) 교정교열
- `copy-editor` 호출: 원고 직접 수정 + `reviews/chNN-copyedit.md` + 용어집(`glossary.md`) 갱신. 편집장은 "제안 항목"만 직접 판단해 처리.

### 3) 감수 (논픽션)
- `fact-checker` 호출: 원고 + 자료카드 경로. 보고서 `reviews/chNN-factcheck.md`.
- 오류·불확실·[확인필요]가 있으면 → `writer`(수정 모드)로 정정 → `fact-checker`가 정정 부분만 재확인. 최대 2회.
- 문학이면 고증 항목이 있을 때만 수행.

### 4) 최종 게이트
- `red-team-reader` 호출: 원고, 기획안(페르소나), 슬롭 체크리스트, 장르 가이드 경로 명시. 판정문 `reviews/chNN-redteam-rN.md`.
- **반려** → 판정문 첨부해 1)부터 다시 (단, 반려 사유 범위만). 최대 2회, 초과 시 사용자 에스컬레이션. **이 판정은 편집장이 뒤집을 수 없다.**
- **조건부 통과** → `writer`가 명시 항목 수정, 편집장이 수정 확인 후 통과 처리.

## 마무리

- STATUS.md 퇴고 칸 갱신 (라운드 수 포함).
- **보고:** 최종 판정, 라운드별로 무엇이 바뀌었는지 2~3줄, 남은 리스크. 다음 단계(`/illustrate` 또는 다음 챕터) 안내.
